## 2. 素材の入れ方

**共通の鉄則**: 素材を追加・差し替えたら **`npx expo start -c` でキャッシュを消して起動する。**
「入れたのに反映されない」の原因はほぼこれで、コードを疑って時間を溶かしやすい。

また、いただいたが使わなかった素材は**捨てずに `assets/未使用/` へ移し、`assets/未使用/README.md` に見送った理由を1行書く。**
既存の記述がその書き方の見本になっている。あとから方針が変わったときに戻せるようにするためで、卒業研究として「なぜ採用しなかったか」を説明できるようにする意味もある。

### 2-1. 街の背景（静止画・PNG）

```
置き場所: assets/home/<街コード>/<時間帯>/png/<街コード>_<時間帯>_lv<N>.png
実例:     assets/home/nightTown/night/png/nightTown_night_lv3.png
登録先:   src/constants/townArt.ts
```

- 街コード: `nightTown` / `castleTown` / `starHill` / `snowTown`
- 時間帯: `sunrise` / `day` / `sunset` / `night` / `latenight`
- レベル: `lv1` 〜 `lv5`
- **1街につき25枚**（時間帯5 × レベル5）
- **サイズは 1672 × 941（16:9）に揃える**。理由は §3 を読むこと
- 空の色は画像に焼き込む（アプリ側でオーバーレイする仕組みは無い）。雨・雪・霧は描き込まない（天気は別レイヤーで上に重なる）

登録は `TOWN_ART` に `require` を1行足すだけ。**React Native の `require` は動的パスを解決できない**ため、必ず静的な文字列で書く。
未登録の時間帯は `night` へフォールバックする（＝ `night` さえあれば表示は壊れない）。

### 2-2. 街の背景（ループ動画・MP4）

```
置き場所: assets/home/<街コード>/<時間帯>/mp4/<街コード>_<時間帯>_lv<N>.mp4
複数パターン: 末尾に連番 → <街コード>_<時間帯>_lv<N>_1.mp4 / _2.mp4
登録先:   src/constants/townVideo.ts
```

- **登録には `require` に加えて幅・高さ（px）を手で書く必要がある。** 静止画は実寸を取得できるが動画は取得できず、スワイプ探索の可動域計算に使うため
- その幅・高さは**対応する静止画と同じ値**にする（ずれるとパンの範囲が静止画と変わる）
- **対応する静止画は必ず残す**（読み込み中の下敷き・設定オフ時・サムネイルに使う）
- 静止画と違い、**時間帯のフォールバックはしない**（`night` の動画を昼に流用しない。空の色と時刻が食い違うため）
- 規格: 無音 / H.264・yuv420p / 尺8〜15秒 / 先頭と末尾のコマを一致させたループ / 1本2〜5MB目安

### 2-3. 天気の演出（背景に重ねる動画）

```
置き場所: assets/home/weather/<天気コード>_<連番>.mp4
実例:     assets/home/weather/rainy_night_1.mp4
登録先:   src/constants/weatherEffect.ts
```

天気コードは `night_weather.code`（`db/chill_night_town_シードデータ.sql` にある11種）。

| コード | 名前 | 演出 | 環境音 |
| :--- | :--- | :--- | :--- |
| `starry_night` | 星空の夜 | ✗ | ✗ |
| `moonlight_night` | 月灯りの夜 | ✗ | ✗ |
| `full_moon_night` | 満月の夜 | ✗ | 虫の音 |
| `dark_night` | 闇夜 | ✗ | 夜風 |
| `cloudy_night` | 雲間の夜 | ✗ | 夜風 |
| `rainy_night` | 雨音の夜 | ✅ 3本 | 雨 |
| `stormy_night` | 嵐の夜 | ✅ 4本 | 雷入りの雨 |
| `snowy_night` | 雪明かりの夜 | ✅ 3本 | ✗ |
| `silent_night` | 静寂の夜 | ✗ | ✗ |
| `foggy_night` | 霧の夜 | ✗ | 夜風 |
| `fireworks_night` | 花火の夜 | ✅ 1本 | ✗ |

- **素材の作り方が特殊**: アルファチャンネルは使えない（H.264 に無い）。**真っ黒な背景に、見せたいものだけを明るく描いた MP4** を用意し、描画側で `mixBlendMode: "screen"` を掛けて黒を抜く
- そのため**暗くする表現は作れない**（豪雨で街が沈む等）
- 濃さは登録時の `opacity` で調整する。既存はすべて 0.8
- 1つの天気に複数パターンを登録できる。**どれを流すかは学習日ごとに決まり、同じ夜のあいだは変わらない**（`src/lib/video-variant.ts`。乱数を使わない理由も同ファイルにある）
- **解像度を揃える必要はない**（画面いっぱいに敷くだけで、スワイプ探索の対象外のため）
- 未登録の天気は演出なし（＝ニュートラルな夜空）で正常に動く。**慌てて埋めなくてよい**

### 2-4. 音（環境音・効果音・鐘）

```
登録先: src/constants/audioAssets.ts
```

| 種類 | 定数 | 置き場所 | 備考 |
| :--- | :--- | :--- | :--- |
| BGM | `BGM` | `assets/audio/bgm/...` | キーは `ambient_sound.code`。曲名・クレジットはマスタ側 |
| 環境音 | `AMBIENT` | `assets/audio/ambient/` | 天気との対応は `src/lib/ambient-select.ts` の `WEATHER_TO_AMBIENT` |
| 効果音・鐘（共通） | `SFX` | `assets/audio/ambient/` | `bell` / `break_notice` / `pomodoro_phase` / `ui_tap` |
| 街ごとの鐘 | `TOWN_BELL` | `assets/audio/bell/<街コード>/` | 未登録の街は共通の鐘へフォールバック |

- **環境音はループし続ける**（`AudioContext.tsx` の `applyAmbient`）。数秒の単発音は使えない。継ぎ目なく流せる長さの素材にすること
- **同梱するのは mp3 のみ**。wav は同じ内容で容量が約10倍になる。原本は `assets/未使用/環境音/wav原本/` に保管する運用
- **街ごとの鐘は現在 wav を参照している暫定状態。** mp3 化して差し替えるのが残作業
- 音色は街ごとに変えてよいが、**やわらかい余韻という気分は全街共通**にする
- 未登録の音は「鳴らす経路はあるが無音」で通る。**登録するまでエラーにはならない**

## 3. 見つかっている不整合 — 背景の解像度がバラついている

**`nightTown` 以外の3街で、25枚の中に別サイズの画像が混ざっている。** 全100枚を実測した結果は次のとおり。

| 街 | 実測 |
| :--- | :--- |
| `nightTown` | 1672×941 が25枚 — **問題なし** |
| `castleTown` | 1672×941 ×16 / 1671×941 ×7 / 1670×941 ×1 / **1659×948 ×1**（`sunrise/lv2`） |
| `starHill` | 1672×941 ×18 / 1669×942 ×2 / 1670×942 ×2 / 1670×941 ×1 / 1671×941 ×1 / 1672×940 ×1 |
| `snowTown` | 1671×941 ×9 / 1670×942 ×9 / 1672×941 ×7 |

**なぜ問題か**: `src/components/pannable-backdrop.tsx` が画像の実寸から表示倍率とスワイプの可動域を計算している。
同じ街の中でサイズが違うと、**レベルが上がった瞬間・時間帯が切り替わった瞬間に、街の見える位置と動かせる幅が変わる**。

1〜3px の差は目視ではまず分からないが、`castleTown` の `sunrise/lv2` だけは **13px 狭く7px 高い**ため、その1枚に切り替わったときだけ画角が動く可能性がある。

**対応の方針は人間に確認すること。**「全部 1672×941 に揃え直す」のがきれいだが、**リサイズは絵に手を入れる行為**であり、制作したチームメイトの成果物を勝手に加工してよいかはこちらで判断できない。少なくとも `castleTown/sunrise/lv2` の1枚は報告する価値がある。

再測定はこれで行える（プロジェクト直下で実行）。

```bash
node -e "
const fs=require('fs');
for(const t of ['nightTown','castleTown','starHill','snowTown']){
  const s={};
  for(const d of ['sunrise','day','sunset','night','latenight']) for(let l=1;l<=5;l++){
    const f='assets/home/'+t+'/'+d+'/png/'+t+'_'+d+'_lv'+l+'.png';
    if(!fs.existsSync(f)){ (s.MISSING=s.MISSING||[]).push(d+'/lv'+l); continue; }
    const b=fs.readFileSync(f), k=b.readUInt32BE(16)+'x'+b.readUInt32BE(20);
    (s[k]=s[k]||[]).push(d+'/lv'+l);
  }
  console.log('== '+t);
  for(const k in s) console.log('   '+k+' : '+s[k].length+'枚'+(s[k].length<25?'  -> '+s[k].join(', '):''));
}
"
```

## 4. 開発用テストボタンを隠す（**方式は未決定**）

### やりたいこと

**Expo Go は開発ビルド扱いなので `__DEV__` が常に true** であり、いまのままだと卒業研究のデモ中もホーム画面下部に開発用パネルが出続ける。これを普段は見えないようにしたい。

ただし**テスト用データの投入手段は残す必要がある。** カレンダー（要件4章）は過去日の記録が無いと何も見えず、本番のタイマーでは当日ぶんしか作れないため、デモの前にダミー記録を入れる必要があるからである。

### 方式は人間が決める（勝手に決めないこと）

隠し方は仕様に定義が無い。**2026-09-09 時点で「後で決める」となっている。** 着手する前に必ず確認すること。検討した選択肢と影響範囲は次のとおり。

| 案 | 内容 | 触る場所 |
| :--- | :--- | :--- |
| A | 隠し操作（ホームの特定箇所を長押し等）で出す | `src/app/index.tsx` のみ |
| B | 設定画面の最下部に「開発用」節を作る | `src/app/index.tsx` ＋ `src/app/settings/index.tsx` |
| C | 別画面 `/dev` に移す | 新規ルート追加 ＋ `src/app/index.tsx` |
| D | ダミー記録の投入ボタンだけ残す | `src/app/index.tsx` のみ。レベル循環・時刻上書きが使えなくなる |

### 現在の実装

開発用パネルは `src/app/index.tsx` の **`DevPanel`**（1572行付近）に集約されている。`if (!__DEV__) return null;` で本番ビルドからは消える。
ボタンは8つ: レベル循環 / 時刻の上書き / 今夜の学習時間を初期化 / カレンダー用のダミー記録 / レベルアップ閾値の切替 / 時刻を+30分 / テスト通知 / データ初期化。

**各ボタンの挙動・目的・落とし穴は `docs/開発用テストボタン.md` に1つずつ書いてある。** とくに次の2点は隠す作業の前に読むこと。

- **時刻の上書きはメモリ上のオフセット**であり、再起動で実時間へ戻る。中断復元の確認には使えない
- **レベルアップ閾値はマスタを書き換える**ため「データ初期化」では戻らない。テスト値のまま放置しないこと

同ファイル末尾の**「撤去チェックリスト」も未消化の項目が残っている。** 今回の作業と重なるため、隠す方式が決まったらチェックリスト側も更新すること。
