# Chill Night Town 要件定義書（機能要件）v2

本章は、初期の要件定義書（完成版）をベースに、要件レビューおよび仕様検討を通じて決定した内容を反映した機能要件（1〜12）の改訂版である。現段階（卒業研究期間内）で実装する範囲を **MVP** とし、今回の実装対象外とする機能には本文中に **【将来拡張】** と明記する。

本書はシステムの利用者・開発者が仕様を理解するための文書と位置づけ、データベースのテーブル名・カラム名といった実装レベルの詳細は記載しない。データベースの詳細設計はER図・SQL定義・テーブル定義書を参照すること。

本アプリは「夜に勉強する人へ寄り添い、学習を継続しやすくする」ことを目的とした感情支援型学習アプリである。仕様・UIの判断に迷った場合は、以下のコンセプトを最優先とする。

- 夜の静かな雰囲気を感じられること
- 勉強への没入感を損なわないこと
- ユーザーに安心感や癒しを与えること
- シンプルで直感的に操作できること
- 「勉強を継続したくなる体験」を提供すること
- 勉強することを強調させないこと

## 1\. 初期設定機能

### 1.1 起動

アプリを初めて起動した際、初期設定画面へ遷移する。2回目以降の起動では、初期設定が完了していればホーム画面へ直接遷移する。

未終了のセッション（3.2参照）が存在する状態で起動した場合は、保存済みの時刻情報からセッションを復元し、終了処理（成果記録）へ誘導する。

### 1.2 初期設定入力

初回起動時、以下の項目を入力・選択し、ユーザー設定として保存する。

| 入力項目 | 内容 |
| :---- | :---- |
| ニックネーム | 必須項目。以後、アプリ内の表示名として使用する。 |
| 一日の学習目標時間 | 必須項目。分単位で入力する（値域: 10分〜720分）。習慣型（6.2参照）における経験値獲得の判定基準および休憩提案（5.1参照）の基準に使用する。 |
| 好みの街の選択 | 用意された街（MVPでは2種類）から1つを選択する。以後「選択中の街」として管理する。 |
| 通知のON/OFF | 学習開始予定時間の通知設定（詳細は12章）。 |

入力完了後、以下の項目は既定値で自動的に作成され、後から設定画面（10章）で変更できる。

- 成長方式: 習慣型（6.2参照）
- 音量設定: BGM 50／環境音 50／効果音 50／鐘の音 50（9章参照）
- 感情記録: ON（3.4参照）
- タイマーモード: 黙々モード（3.1参照）

**本アプリは1端末＝1ユーザーを前提とし、ログイン機能および複数アカウント機能は実装しない。** ユーザー情報は端末内に常に1件のみ保持する。**【将来拡張】** 将来的にFirebase等のクラウドサービスと連携し、複数端末間でのデータ同期や認証機能に対応できるよう設計を考慮している。

### 1.3 チュートリアル（使い方）

初めての人が迷わないよう使い方を案内する。ただし**初回に一度に見せる量は最小限**にし（説明が多いと頭に入らず負担になるため）、残りは**各機能に初めて触れたときに一つずつ**出す。

- **初回チュートリアル（初期設定の完了直後・一度だけ）**: ホーム画面でスワイプ式カルーセルを表示し、**まず始めるのに要る最小限**だけを案内する（タイマーで学習／街が育つ／眺める・横向き）。画面の配置そのものの説明は置かない（見れば分かることを言葉で足すと初回の分量が増えるうえ、UIを直すたびに説明とのずれが生まれるため）。閉じたか最後まで見たら表示済みとして記録し（`user.tutorial_completed`）、以降は自動表示しない。
- **機能ごとの初回説明**: 上記以外（夜の天気と環境音／カレンダー／夜の住人／おやすみ）は、**初めてその画面・操作に触れたとき**に一度だけ、その機能の説明を出す（例: 初めてカレンダー画面を開いたとき／初めて設定の「夜の住人」を開いたとき／初めておやすみを押したとき）。**天気の説明は、ホームからでもタイマー設定からでも、初めて天気の選択欄を開いたときに選択欄の上に重ねて出す**（どちらか片方で見れば再表示しない）。見た機能はキー集合で記録する（`user.tutorial_seen_features`）。
- 以降は**設定（10章）の「使い方」を開くと各機能の説明が一覧され、項目を選ぶとその説明を読める**（「最初から見る」で通し再生）。設定からの閲覧は上記いずれのフラグにも影響しない。
- 文体はコンセプト準拠（静か・責めない・急かさない）。当面はテキスト中心で、説明画像はアート/UI確定後に差し込む。
- 初回チュートリアルを閉じた後に、成長方式のお知らせ（6.2）を表示する（チュートリアル → お知らせ の順）。

## 2\. ホーム画面機能

### 2.1 ホーム画面表示

ホーム画面には、日付、今日（当学習日）の学習時間、目標達成状況、選択中の街のレベル、状況に応じたメッセージ（7章のNPCメッセージ）、疑似オンライン人数（11章）を表示する。画面の初期表示位置は、選択中の街の中央エリア（住宅街）とする。

画面の隅にカレンダー画面（4章）・設定画面（10章）への導線となるアイコン、おやすみボタン（13章）、および鑑賞モードボタン（2.4）を配置する。街の全景を遮る常設のナビゲーションバーは、没入感を損なうため設けない。

また、画面下部にBGMミニプレイヤー（9章）を常時表示する（タイマー計測中も表示を継続する。BGMの音量が0でも表示し、音は鳴らさない）。

タイマー稼働中は、画面隅に計測中インジケータ（経過時間、ポモドーロモードの場合は現在フェーズ）を常時表示する。インジケータをタップするとタイマー表示（3.2）を再展開する。

### 2.2 街探索

ユーザーはスワイプ操作で背景を左右にスクロールし、選択中の街を探索できる。街は1枚の横長背景画像で構成し、シームレスに表示する。街の成長段階（6章参照）に応じて、表示される建物・オブジェクトが増加する。

#### 背景のループ動画（任意）

背景素材は静止画を基本とするが、**素材が用意された街・時間帯・成長段階に限り、ループ再生する短い動画（灯りの揺らぎ・波など）を背景に用いてよい**。動画は次の条件を満たすものとする。

- **無音で再生する**（BGM・環境音・効果音の再生を妨げない）
- 静止画と**同じ構図・同じ画角**とし、スワイプ探索（本節）の可動域を静止画のときと変えない
- 継ぎ目が分からないよう、先頭と末尾がつながるループとする
- 動画が用意されていない組み合わせは、従来どおり静止画を表示する（ある時間帯の動画を別の時間帯へ流用しない）
- 1つの組み合わせに、**構図は同じで動きだけが違う複数のパターン**を用意してよい。その場合、どのパターンを流すかは**学習日ごとに決まる**（同じ夜のあいだは切り替わらない）。夜ごとに街の表情がわずかに変わることで、毎晩帰ってくる場所としての鮮度を保つため

動画の再生は設定「背景を動かす」（10.11）でオフにでき、オフのときは静止画を表示する。長時間の表示（横画面での置き時計利用など）における電池消費をユーザー自身が選べるようにするための措置である。

また、**おやすみ（13章）の暗転しきった後は再生を止める**。背景が見えていない間に再生を続けても電池を消費するだけであり、音を止めて夜を閉じるという本機能の趣旨とも合わないため。復帰と同時に再生を再開する。

### 2.3 学習開始

学習タイマーは、夜間帯（18:00〜翌5:00）のみ開始できる。時間帯の判定はホーム画面の表示時および時刻の変化時に行い、時間帯外は学習開始ボタンを非活性化したうえで、開始できない旨のメッセージを表示する。

学習開始ボタンを押すと、タイマー設定モーダル（3.1）を表示する。

### 2.4 鑑賞モード・横画面表示

#### 鑑賞モード（UI一括非表示）

- ホーム画面の鑑賞モードボタン（目のアイコン）を押すと、ホーム画面上のすべてのUI（日付・学習状況・レベル・NPCメッセージ・疑似オンライン人数・学習開始ボタン・計測中インジケータ・BGMミニプレイヤー・各アイコン。**鑑賞モードボタン自身を含む**）を非表示にし、夜の街の背景のみを表示する。
- 非表示中も、スワイプによる街探索（2.2）は可能とする。音声はすべて通常通り再生を続ける（音を止めて夜を閉じる「おやすみ機能」との役割の違い）。
- **画面をタップするとUIを復帰する。**
- タイマー稼働中も使用できる。表示の切り替えのみであり、計測・判定・記録には一切影響しない。
- 非表示中に休憩提案（5.1）・ポモドーロの全ループ完了・5:00自動終了（3.2）等のシステム側のイベントが発生した場合は、UIを自動的に復帰させてから該当の表示を行う。
- 鑑賞モードの状態は保存しない（アプリ再起動時は通常表示から始まる）。

#### アイドル最小表示（無操作時）

- ホーム画面を開いたまま**30秒間何も操作しない**と、操作系UI（天気・学習仲間・学習状況・レベル・BGMミニプレイヤーの操作・各アイコン・鑑賞モードボタン等）を隠し、**最小限の情報だけ**を残した静かな表示へ移る。夜の街の背景はそのまま透かす。
- 残すのは**バッテリー・日付・現在時刻（大きく表示）・再生中の曲名**。**計測中のときだけ**、右上に時計と「作業中」インジケータも残す（計測状況が分かるように）。未計測時は時計も隠す。
- **画面のどこかに触れると通常表示へ戻る**（無操作の計測もやり直す）。移行はフェードで静かに行い、急に変えない。
- ただし**計測中の時計はタップでそのままタイマー表示（詳細）へ進める**（最小表示を挟まず操作できる）。時計以外の場所は通常表示への復帰に使う。
- 鑑賞モード・横画面・各モーダル（タイマー設定・タイマー表示・成果記録）表示中は移行しない。
- ただし**最小表示中に端末を横向きにして縦へ戻した場合は、最小表示のまま維持する**。横画面は同じ「街を眺める」状態の別の見せ方であり、端末を回して戻しただけで通常表示に戻ると、最小表示にした意図が失われるため。解除はあくまで**画面に触れたとき**とする。
- スリープは**OS標準に従う**（未計測時に常時点灯はしない＝省電力）。計測中は従来どおりスリープを防止する（3.2）。
- アイドル表示の状態は保存しない。

#### 横画面表示（ホーム画面限定）

- 端末を横向きにすると、ホーム画面はUIを非表示にした鑑賞表示となり、**背景画像（街の全景）を1画面につなげて表示する**。全景が収まるためスクロールは不要であり、スワイプによる街探索は行わない。
- 背景の上に、**アイドル最小表示と同じ最小UI**を重ねて表示する（統一）。内容は バッテリー・日付・大きな現在時刻・再生中の曲名。**タイマー稼働中のみ**、時計＋「作業中」インジケータも重ねる。
- **画面をタップするたびに、この情報表示の表示／非表示を切り替える**（非表示にすると街の全景のみになる）。
- 横画面は**閲覧専用**とする。情報表示の切り替え以外の操作——**タイマーの操作（一時停止・再開・終了）を含む——は一切行えない**。タイマーを操作したい場合は端末を縦向きに戻す。
- 端末を縦向きに戻すと、通常表示（UIあり）に復帰する。縦向きに戻すことが通常表示への唯一の復帰操作である。
- 横画面に対応するのは**ホーム画面のみ**とし、タイマー設定・成果記録・カレンダー・設定などの操作系画面はすべて縦固定とする。
- 横画面中にシステム側のイベント（5:00自動終了等）が発生した場合は、画面を縦向き表示へ戻したうえでUIを復帰し、該当の処理を表示する。
- 背景素材は、横向き表示時に見える上下の範囲を考慮した高さ（またはセーフマージン）で制作すること（素材制作前の必須確認事項）。

**【将来拡張】** ホーム画面以外の画面の横画面対応。

### 2.5 今夜の天気の選択（ホーム画面）

夜の天気（3.4の11種類）は、**学習を開始しなくてもホーム画面から選択できる**。選択した時点から、その学習日の背景演出（8章）・環境音（9章）へ即座に反映する。

- **その学習日の天気が未選択の場合、18:00以降のホーム画面に「今夜はどんな夜？」等の控えめな案内カードを表示する。** カードには**対象の学習日**（例: 1/10（金）の夜）を併記し、どの日の記録として扱われるかを明示する。
- 案内カードは**モーダルではなく、操作を妨げない形**で表示する。閉じることができ、閉じても天気は後から選べる。**天気の選択は必須ではない**（ただし学習タイマーの開始時には必須。3.1）。
- **ホーム画面の情報表示（日付・今夜の学習仲間・今夜の学習時間と同じ並び）に、その夜の天気を1行で常時表示する**（例: 🌧 雨音の夜／未選択時は「今夜の天気を選ぶ」）。この行をタップすると天気を選択・変更できる。**専用の常設ボタンは設けない**（ホーム画面は既に多くのUIを抱えており、街の全景を遮らない方針〈2.1〉に反するため）。天気は「今夜の状態」を表す情報であり、日付・学習時間と同じ並びに置くのが自然である。
- 18:00より前にホーム画面を開いていた場合は、**18:00に到達した時点でカードを静かに表示する**。ただし鑑賞モード中（2.4）・横画面中・タイマー設定モーダル表示中は表示せず、通常表示へ戻った時点で表示する。
- **選択済みの学習日にはカードを表示しない**（情報表示の天気の行からの変更は常に可能）。
- 天気の選択・変更は、この画面のほかタイマー設定（3.1）・学習成果記録（3.4）・**カレンダーの日別詳細（4.1・その学習日がまだ終わっていない場合に限る）**からも行える。**1晩＝1天気**とし、いずれの経路から選び直しても、**その学習日の天気を上書きする（最後の選択が残る）**。カレンダーを経路に含めるのは、写真（2.6）がそこから撮れるのに天気だけ選べないのが不自然なためであり、**過去の夜を変更できるようにするものではない**。
- 天気は**学習日単位**で保持し、前日以前の天気は引き継がない（8章）。変更できるのは**その学習日が終わる（5:00）まで**であり、学習日が変われば新しい夜となる。過去の夜の天気は変更しない（カレンダーからも夜の天気は編集対象外。編集できるのはタグ・メモのみ・4.1）。

> **補足**: 本機能は当初【将来拡張】としていたが、天気がタイマー開始まで選べないと、街に帰ってきただけでは夜の空気が立ち上がらず、コンセプト（またこの世界に帰ってきたい夜の街）と噛み合わないためMVPへ移した。ただし起動時に選択を強制すると入口に関門を作ることになるため、**非強制・非モーダル**とする。

### 2.6 今夜の写真

その夜の外の様子を1枚だけ写真に残し、**その夜の天気に添える**ことができる。天気の選択を置き換えるものではなく、**任意の付加機能**である（背景演出〈8章〉・環境音〈9章〉は従来どおり天気のみに依存する）。

**撮影の順番と画面構成**

- 撮影と天気の選択は、**同じ選択欄（2.5の「今夜はどんな夜？」）の中で縦に2段**に並べる。上段が写真、下段が天気であり、**写真 → 天気の順**に並ぶ。実際に外を見て撮り、その写真を見ながら「今夜はどんな夜だったか」を選べるようにするためである。
- 写真を撮った直後、その学習日の天気が未選択の場合は、下段の見出しを「この夜はどんな夜だった？」等に変え、天気の選択へ静かに続ける。**強制はしない**（写真だけ残して閉じてよい）。
- 天気を選ぶと選択欄は閉じる（従来どおり）。天気は流れの最後の行為であるため、順番と矛盾しない。
- **ホーム画面に写真専用の常設ボタンは設けない**（2.5と同じ理由）。入口は天気の選択欄の中のみとし、ホーム・タイマー設定（3.1）・学習成果記録（3.4）のいずれから開いても同じ形で現れる。

**取得方法・保存**

- **カメラ撮影のみ**とし、端末内の写真ライブラリからの選択は行わない。「その夜の外を確かめる」体験のための機能であり、任意の過去の写真を入れられると「その夜の記録」でなくなるためである。
- 撮影した画像は**長辺1280px・JPEG品質0.7程度に再エンコードして保存**する。主目的は**EXIF（撮影位置情報等）の除去**であり、容量削減は副次的な効果である（セキュリティ方針を参照）。
- 保存先は端末内のアプリ専用領域とし、**外部への送信・共有・書き出し機能は設けない**。
- 撮影の失敗・保存の失敗時は、責めない文言で静かに知らせる。**ファイルの保存が成功してからDBを更新する**（逆順では実体のない参照が残るため）。

**帰属・枚数・変更**

- 写真は**1学習日につき1枚**とし、撮り直した場合は上書きする（履歴は持たない）。1晩＝1天気（2.5）と同じ考え方による。
- 帰属する学習日は、**撮り始めた時刻**が属する学習日とする（0章の定義に従う。セッションの帰属が開始時刻によるのと同じ）。保存の完了時刻では判定しない。例: 1/11 4:58に撮り始めて保存が5:01になった写真は「1/10の夜」に属する。
- 一方、**表示にはEXIFではなくアプリが記録した実際の撮影時刻を用いる**（例: 1/10の夜の記録として「1/11 1:30 に撮影」と表示する）。日付をまたいで撮った写真が前日の記録に入ることへの違和感は、学習日の定義を変えるのではなく、**「〜の夜」という表記と撮影時刻の明示によって解消する**。
- **撮影できるのは夜間帯（18:00〜翌5:00）のあいだのみ**とする。天気は心象であり夜が始まる前に選べる（2.5）が、写真は「その夜の外の様子」という実像であり、昼間に撮れると「今夜の空」と称して昼の空が記録に入るためである。学習タイマーを開始できるのが夜間帯だけである点（2.3）とも揃う。
- 追加・撮り直しができるのは**その学習日が終わる（5:00）まで**（天気と同じ）。この制限は**経路によらず同じ**であり、選択欄からでもカレンダー（4.1）からでも、当該の夜のあいだは撮り直せる。**削除だけは過去の夜も含めていつでも行える**（カレンダー・4.1）。写真は部屋や人物が写り得るため、後から消せないのは不適切だからである。削除は取り消せないため、責めない文言で一度だけ確認する。
- **天気が未選択の夜でも写真だけを残せる**。写真を先に撮る順番である以上、天気が決まる前に写真が存在し得るためである。

**表示**

- カレンダーの日別詳細（4.1）で、その夜の天気とあわせてサムネイルを表示する。タップで全画面表示し、そこから削除できる。**月の一覧（マス）には写真を表示しない**（静かな月表示を保つため）。
- **月次サマリー・夜の天気アルバム（4.2）には写真を含めない**。アルバムは選択された天気の集計であり、その性格を変えないためである。

**機能のON/OFF設定は持たない（改訂51）**

- 撮影の入口は、その夜が終わる（5:00）までのあいだ**常に表示する**。設定による表示・非表示の切り替えは行わない。
- **カメラ権限は、利用者が撮影を選んだ時点で初めて要求する。** 撮影を選ばなければ権限を要求せず、写真も一切保存されない。カメラを使いたくない利用者への配慮は、設定ではなく**この仕組みそのもの**で満たす。
- 当初は設定「夜の写真」（10.14）でOFFにできる設計だったが、OFFにしてもしなくても、撮らない利用者に起きることは同じであり（差は選択欄に写真の枠が見えるかどうかだけ）、設定が実際に防ぐものが無かったため廃止した。

## 3\. 学習タイマー機能

学習タイマーは独立した画面ではなく、ホーム画面（夜の街）の上に重なる表示として構成する。学習中もユーザーは夜の街の中に留まり続ける。

### 3.1 タイマー設定（開始前）

学習開始ボタン押下後、タイマー設定モーダルを表示する。設定項目は以下の通り。

| 設定項目 | 内容 |
| :---- | :---- |
| 今夜の天気 | 11種類（3.4参照）から1つを選択する。**その学習日の天気がまだ選ばれていない場合は必須**。すでに選択済みの場合（ホーム画面 2.5 での選択、または同じ学習日の過去の学習開始時の選択）は、その選択を引き継いで表示し、変更も可能。選択した天気は、**開始ボタンを押した時点で**その学習日の天気として確定し（1晩＝1天気・上書き）、ホーム画面・学習中の背景演出（8章）および環境音（9章）に反映される。 |
| タイマーモード | 「黙々モード」「ポモドーロモード」から選択する。前回選択したモードを記憶し、次回は選択済みの状態で表示する。 |
| （黙々モード）予定学習時間 | 予定する学習時間を分単位で設定する（値域: 10〜660分、既定値60分）。 |
| （ポモドーロモード）作業時間・休憩時間・繰り返し回数 | 作業時間（値域: 5〜120分、既定値25分）、休憩時間（値域: 1〜30分、既定値5分）、繰り返し回数（値域: 1〜10回、既定値1回）を設定する。 |

**設定値はモードとあわせて記憶し、次回は前回の値を入れた状態で表示する。** 毎回同じ時間を設定し直す手間を省くため。既定値は初回のみ使用する。

記憶は**入力を終えた時点**で行い、開始しなくても次回に引き継ぐ。設定を見直しただけで閉じた場合にも、その値を覚えていてほしいため。ただし**値域外の値は記憶しない**（次回に開始できない値が入った状態で開くのを避けるため）。

#### タイマーモード

- **黙々モード**: 設定した予定学習時間に向かって連続で計測する。従来型のタイマー。
- **ポモドーロモード**: 作業フェーズと休憩フェーズを交互に繰り返す。作業フェーズを設定した繰り返し回数だけ行い、**休憩フェーズは作業と作業の間にのみ挟む（最後の作業フェーズの後に休憩は行わない）**。すなわち繰り返し回数 n の構成は「作業 →（休憩 → 作業）× (n−1)」となり、総経過時間は 作業×n ＋ 休憩×(n−1) となる（繰り返し回数が1回の場合、休憩は発生しない）。フェーズの切り替わりは自動で行い、切り替わり時には控えめな効果音（鐘とは別の音）を再生する。**最後の作業フェーズの完了をもって全ループ完了**とし、終了演出（3.3）を行う。切り替わり音の再生はアプリがフォアグラウンドにある間のみ行い、**バックグラウンドにある間はOSのローカル通知でフェーズの切り替わりと全ループ完了を知らせる**（12章参照。設定でON/OFFできる）。**休憩フェーズのあいだは、実績学習時間の代わりに休憩の残り時間を表示する**（実績学習時間は休憩を含まないため、休憩中は数字が止まり、計測が壊れたように見えるため）。

### 3.2 タイマー計測

学習タイマーは開始・一時停止・再開が可能で、1回のセッション中に繰り返し操作できる。タイマー開始時に設定した**予定学習時間**（ポモドーロモードの場合は作業時間×繰り返し回数）と、実際に学習した**実績学習時間**をそれぞれ記録する。これにより「予定60分に対して実績40分」のような差分を保持できる。

#### 計測方式

経過時間は、開始・一時停止・再開の各時刻を操作のたびに端末へ保存し、**現在時刻との差分**から算出する（カウンター方式は用いない）。バックグラウンドでの処理実行は行わないが、この方式によりアプリを離れて戻った場合でも経過時間は正しく引き継がれる。

#### 中断からの復元

アプリの強制終了・クラッシュ・端末再起動などでセッションが終了処理を経ずに中断された場合、次回起動時に保存済みの時刻情報からセッションを復元し、「前回のセッションが終了していません」として終了処理（成果記録）へ誘導する。復元時点で5:00を過ぎていた場合は、5:00終了のセッションとして扱う。

#### 5:00到達時の自動終了

タイマー稼働中（一時停止中を含む）に翌5:00に到達した場合、自動的に終了演出（3.3）へ移行し、実績学習時間は5:00までとする。この仕様はタイマー開始時に画面上で明示する。

#### 実績1分未満のセッションの破棄

実績学習時間が1分未満の状態で終了（手動終了・5:00自動終了・中断復元時を含む）した場合、終了演出・成果記録へは進まず、**セッションを保存せずに破棄**する。「1分未満のため記録されませんでした」等の控えめなメッセージを表示してホーム画面へ戻る。街への加算・成長判定は行わない。誤って開始してしまった場合は、すぐに終了すれば記録が残らない。

なお、**その学習日の天気（2.5）は破棄しない**。天気の選択は学習セッションから独立した行為であり（ホーム画面からも選択できる）、セッションの破棄によって選び直しを強いるのは不自然なため。天気を変えたい場合はホーム画面の天気の行から変更できる。

#### 端末時刻の変更への耐性

経過時間の差分計算の結果が負の値になった場合（ユーザーによる端末時計の変更等）は、0に丸めて扱う。

#### 画面スリープの防止

タイマー稼働中（一時停止中を含む）は、OSの画面スリープを防止する。あわせて、横画面表示中および鑑賞モード中（2.4）もスリープを防止する。それ以外の場面ではOS標準のスリープ動作に従う。

#### タイマー表示の折りたたみ

タイマー表示は「×」操作で折りたたみ、街（ホーム画面）へ戻ることができる。計測は継続され、計測中であることはホーム画面のインジケータ（2.1参照）で表示する。学習を「中止」して記録を残さない機能は用意しない。終了は必ず終了演出・成果記録を経由する（感情・タグ・メモは任意項目のため、すぐに保存して閉じることができる）。

#### タイマー稼働中の他画面利用

タイマー稼働中も、他の画面（カレンダー・設定等）へ移動できる。ただし、**進行中のセッションの判定・記録に影響する操作、および破壊的操作は、タイマー稼働中は変更不可とする**。詳細は10章を参照。

### 3.3 終了演出

学習終了時には鐘の音による終了演出を行う。鐘の音の再生中は、BGM・環境音の音量を一時的に下げる（ダッキング）。

### 3.4 学習成果記録

学習終了後、以下の内容を入力・確認し、1件の学習記録として保存する。

| 記録項目 | 内容 |
| :---- | :---- |
| 夜の天気 | その夜に選択済みの天気を表示する。ここで変更することもできる（「振り返ってみたら今夜は嵐の夜だった」を許容する）。**1晩＝1天気**のため、ここでの変更はその学習日の天気そのものを変更する（同じ夜の他の学習記録の表示にも反映される）。 |
| 感情 | 下記11種類から1つを選択する。感情記録の設定がONの場合のみ記録する。 |
| 学習内容タグ | 複数選択できる。標準タグに加え、自由入力によるオリジナルタグ（マイタグ）にも対応する（詳細は本章末尾）。 |
| 振り返りメモ | 自由入力、任意項目。 |
| 開始・終了時刻 | 学習を開始・終了した日時を記録する。 |
| 予定・実績学習時間 | 3.2で記録した内容を保存する。 |

ポモドーロモードの場合も、1式（全ループ）で1件の学習記録とする。ループごとに記録を分割しない。

#### 成果記録画面から離脱した場合

成果記録を保存せずに画面から離脱した場合、セッション（開始・終了時刻、予定・実績学習時間）は自動的に保存・確定する。感情・タグ・メモは未入力（空）のまま確定する。学習した時間（街の成長への加算分）が失われることはない。その夜の天気は開始時に確定済み（2.5 / 3.1）のため、離脱による影響を受けない。

#### 夜の天気（全11種類）

✨ 星空の夜／🌙 月灯りの夜／🌕 満月の夜／🌑 闇夜／☁️ 雲間の夜／🌧️ 雨音の夜／⛈️ 嵐の夜／❄️ 雪明かりの夜／🌃 静寂の夜／🌫 霧の夜／🎆 花火の夜

夜の天気は気象データではなく、「その夜がどんな夜だったか」を表す心象風景として選択するものである。実際の空を見て選んでも、気分で選んでもよい。**【将来拡張】** 実際の気象データ（天気API）との連携による背景演出の補助。

#### 感情（全11種類、3カテゴリ）

- **ポジティブ**: 😊 達成感／🔥 集中できた／💪 頑張れた／😄 楽しかった
- **ニュートラル**: 😌 穏やかだった／😶 いつも通り／😴 眠かった
- **ネガティブ**: 😔 疲れた／😞 少し落ち込んだ／😥 不安だった／😣 思うように進まなかった

#### 学習内容タグ（標準タグ＋マイタグ）

標準タグは以下の5種類とする（マスタデータ）。

**資格勉強／レポート・課題／暗記・復習／プログラミング／読書**

「その他」は標準タグに含めない。**タグは任意項目であり何も選ばずに保存できる**ため、「その他」を選ぶことと何も選ばないことの情報量が変わらず、記録を振り返る際に得るものがないため。分類しきれない内容はマイタグとして具体的な名前で登録できる。

これに加え、ユーザーは自由入力でオリジナルの「マイタグ」を登録できる。マイタグの仕様は以下の通り。

- 初めて入力したタグは以後「マイタグ」として保存し、次回以降は標準タグと同様に選択できる。
- 同一名称のマイタグは重複登録しない。**標準タグと同名のマイタグも登録できず**、その場合は「すでに同じ名前のタグがあります」等のエラーメッセージを表示する（登録時・編集時で挙動を統一する）。
- **標準タグ・マイタグとも設定画面（10章）から編集・削除できる**（不要な標準タグを消せるようにするため。標準/マイタグで扱いを統一する）。**名称の変更は、過去の学習記録の表示にも反映される。**
- 削除は**論理削除**とし、データそのものは残す。削除済みのタグは新規の選択肢には表示されないが、過去の学習記録ではそのまま表示され続ける。
- **削除済みのタグと同名のタグが新たに入力された場合は、削除済みのタグを復活させる**（削除フラグを解除して選択肢に戻す）。新規タグとして別に作成しない。
- **タグは有効なもの（標準＋マイタグ）を合わせて最大20件まで**とする。**削除済み（論理削除状態）のタグは、この上限のカウントに含めない。** 標準タグ5件も枠を消費するため、自作タグは実質最大15件（不要な標準タグを削除すれば、その分だけ自作タグを増やせる）。
- タグ名の上限は20文字、振り返りメモの上限は500文字とする（いずれもアプリ側の入力検証で担保する）。

## 4\. 学習記録カレンダー機能

### 4.1 日別記録の閲覧・編集

カレンダー上で日付を選択すると、その学習日の学習時間、感情、夜の天気、タグ、メモを閲覧できる。日付への帰属は「学習日」の定義（0章）に従う。記録が存在しない日は、その旨が分かるデフォルト表示を行う。

**日別詳細の見出しには、その夜の範囲（例: 1/10（金）の夜 18:00 〜 翌5:00）を併記する。** 学習日は暦日と一致せず、日付をまたいだ記録が前日に属するため、どこからどこまでが「その夜」なのかを画面上で明示する。

**学習記録が存在しない夜でも、選んだ天気（2.5）と写真（2.6）は表示する。** 天気の選択は学習から独立した行為であり（ホーム画面からも選べる）、選んだ時点で背景演出・環境音へ反映され記録として残っている。日別詳細で空にすると、ユーザーには消えたように見えるためである。ただし**月の一覧（マス）と月次サマリー・天気アルバム（4.2）は従来どおり学習記録のある夜のみを対象とする**（マスは「学習した夜」を表し、集計は学習した夜の傾向を見るためのものだから）。

その夜の写真（2.6）がある場合は、天気とあわせて**サムネイルを表示する**。タップで全画面表示し、そこから削除できる。**写真には実際の撮影時刻を添える**（例: 1/11 1:30 に撮影）。日付をまたいで撮った写真が前日の記録に入ることを、表記のうえで矛盾なく読めるようにするためである。写真の削除は取り消せないため、責めない文言で一度だけ確認する。

日別詳細からは、各セッションの**学習内容タグと振り返りメモを後から編集できる**（セッションを長押しして編集する）。過ぎた夜の記録を整えて振り返りの質を高められるようにするためである。一方、**感情・学習時間・過ぎた夜の天気は編集対象としない**。感情はその夜のその時の気持ちのスナップショットであり、後から書き換えると記録が事実でなくなるため閲覧のみとする。学習時間は実績の改ざんになるため変更できない。タグ・メモの入力仕様（標準タグ／マイタグ・重複・上限・メモ500文字）は学習成果記録（3.4）に準ずる。

**写真（2.6）は例外とし、過去の夜のものも含めて削除だけは常に行える**（追加・撮り直しは当該学習日の5:00まで）。

また、**その学習日がまだ終わっていない場合に限り、日別詳細から天気の選び直しと写真の撮影・撮り直しができる**。入口は「今夜の天気と写真」の1つとし、ホーム画面（2.5）と同じ選択欄を開く（天気と写真で別々のボタンを並べない）。記録を眺めていて選び直したくなったときにホーム画面へ戻らせないためであり、**過去の夜は従来どおり変更できない**（可否の判定は経路によらず同じ）。写真は部屋や人物が写り得るため、後から消せないのは不適切だからである。削除は記録の書き換えではなく取り下げであり、上記の「事実を書き換えない」方針とも矛盾しない。

### 4.3 予定・メモ（カレンダーに置く予定）

カレンダーに**予定・メモ**を置ける（例: 8/1にテスト）。予定は**暦日**で持つ（学習日ではなく実カレンダーの日付。その学習は前夜に行う想定）。1日に複数登録できる。

- **予定がある日は、日付の数字を灯り色でそっと示す**（急かす赤ではなく、落ち着いた夜の街の配色に合わせる）。
- 日付を選ぶと日別詳細に**予定**欄が出る。そこから予定の**追加・タイトル編集・削除**ができる（タイトルは30文字以内）。
- **予定を追加できるのは今日（暦日）以降の日付のみ**とし、過ぎた日付には追加の操作を表示しない。予定は「これから帰ってくる夜」のためのものであり、また通知は過ぎた発火時刻を捨てるため、過去日付に登録できると**鳴ることのない予定が黙って作られる**（登録したのに知らせが来ない、とユーザーには見える）。当日は追加できる（「今日提出」を朝に書き足すのは自然なため）。**すでにある予定の編集・削除は、過ぎた日付でも行える**（書き間違いを直せないのは不便であり、削除は記録の改ざんにあたらないため）。
- 過去の記録（過ごした夜）と未来の予定（これから帰ってくる夜）が同じカレンダーに並ぶ。
- 予定の**通知**は10章の通知設定でON/OFFする（既定OFF）。ONのとき、各予定の**1週間前・前日の12:00**にそっとお知らせする。文面は急かさない（カウントダウンや感嘆符で煽らない）。

### 4.2 月次サマリー

月単位で以下の集計情報を表示する。

- 総学習時間
- 学習回数
- 最も多かった感情
- 最も多かった夜の天気
- 感情別の記録回数
- **目標に届いた夜の数**（その月に一日の学習目標時間へ到達した学習日の数）
- **よく学んだ内容**（学習内容タグ別の記録回数）
- **よく灯していた時間帯**（セッションの開始時刻が最も多かった時間帯を1つ）
- **その月のふりかえりメッセージ**（下記）

なお、**夜の天気アルバム**は専用のデータを持たず、選択された夜の天気（2.5）を都度集計して表示する方針とする。月次サマリーに表示するアルバムは**選択中の月**の集計とする。

月次サマリーのアルバムにも、**その月に学習した夜の数に応じた見え方の段階**を設ける（段階の考え方は4.4に準ずる。しきい値は月次: 5夜・15夜）。月ごとに決まるため、過去の月へ戻ればその月の見え方のまま表示される（「先月はこれだけ通った」が分かる）。1か月は最大31夜しかないため、通算（4.4）と同じしきい値は用いない。

**アルバムは「集めるもの」として扱わない。** 収集の進み具合（例:「11種のうち何種」）は表示せず、未選択の天気も並べない。夜の天気はその夜の心象をユーザーが主観で選ぶものであり（2.5）、揃っていない種類を示すと、その夜の実感ではなく**空欄を埋めるために天気を選ぶ**動機が生まれる。そうして選ばれた天気は記録として事実でなくなり、背景演出（8章）・環境音（9章）もその夜の気分と食い違う。アルバムは「その期間がどんな夜の集まりだったか」を映す集計に留める。

#### 月のふりかえりメッセージ（たたえる）

**完了した月に限り**（=今日の学習日がその月の末日を過ぎている場合のみ。進行中の月・記録の無い月には出さない）、その月に記録された感情の**カテゴリ傾向**（ポジティブ／ニュートラル／ネガティブの比率）と**最も多かった感情**に応じて、頑張ったユーザーをたたえる静かな一言を1件表示する。

- 傾向は「ほぼ前向き」「前向き＋穏やか」「前向き＋しんどさが少し散見」「穏やか中心」「拮抗（山あり谷あり）」「しんどさが多かったが続けた」「記録がわずか（感情記録OFF等）」に分類する。しんどい気持ちが多かった月も**責めず、続けられたことを讃える**トーンとする。
- 文面は**傾向 × 住人ごとに3本**を持ち、**年月から決定的に1本選ぶ**。振り返るのは**カレンダーを開いている時点で選択中の住人**（7.1。その住人の月次文面が未整備なら、同じ街の既定の住人が代わりに振り返る）。同じ月は何度開いても同じ文面（安定した振り返り）で、月が変われば別の言い回しになる（同じ傾向が続いても飽きない）。
- 最も多かった夜の天気が記録されている月は、最後に**天気へ軽く一言触れる**。夜の天気はユーザーが主観で選んだもの（実際の空でもあり、その夜の心象でもある。2.5）である点をふまえた言い回しとする。**一言の内容は天気の種類ごとに変える**（天気の名前を言い換えるだけでは、その月の空に触れたことにならないため）。文面は住人 × 天気（11種）× 3本を持ち、**年月から決定的に1本選ぶ**（同じ月は毎回同じ文面、同じ天気が続く月でも言葉は変わる）。文面を持たない天気では何も添えない。
- 読みやすさのため、文面は**文（。）ごとに改行**して表示する。
- これは7.1のNPCメッセージ（学習セッション単位・DBのメッセージマスタから条件マッチ）とは**別系統**で、月次集計から算出する表示専用のメッセージである（DBには保存しない）。

- 集計の対象は**学習記録が存在する学習日のみ**とする。天気だけ選んで学習しなかった夜はアルバムに含めない。
- **1晩＝1天気**のため、「最も多かった夜の天気」は**夜の数**で数える（1晩に複数回学習しても1回と数える）。
- 感情は学習記録ごとに保存されるため、感情に関する集計は学習記録単位で行う。感情が未入力の記録は感情の集計から除外する（学習時間・学習回数の集計には含める）。
- **目標に届いた夜の数は「n夜」とだけ示し、割合・達成率にはしない。** 「30日中12日」のような見せ方は、届かなかった夜を失敗として数える形になり、責めない方針に反するためである。
- **学習内容タグは記録回数（セッション単位）で数える。** 1つのセッションに複数のタグが付いている場合は、それぞれのタグに1回ずつ数える。削除されたタグ（`is_active = 0`）でも、過去の記録に付いているものは集計に含める（記録が後から書き換わらないようにするため）。
- **時間帯はセッションの開始時刻（端末のローカル時刻）で数える。** 夜間帯の外（5:00〜17:59）に開始した記録は「昼」としてまとめる。表示は**グラフにせず「21時台」のように文字で最も多かった時間帯を1つだけ**示す（時間帯まで分布で見せると、月次サマリーがグラフばかりの成績表に近づくため）。同数の場合は、学習日と同じ夜の並び（18時台→翌4時台）で**先に来る時間帯**を採る。

### 4.4 通算のふりかえり

月をまたいだ**全期間の集計**を表示する。月次サマリー（4.2）は月ごとの傾向を見るためのものであり、「これまで通ってきた夜の全体」を見る場所が別に必要なためである。

- 通った夜の数（学習記録が存在する学習日の数）
- 累計学習時間
- いちばん長かった夜の学習時間（学習日ごとの実績学習時間の合計の最大値）
- **目標に届いた夜の数**（全期間）
- **よく学んだ内容**（学習内容タグ別の記録回数・全期間）
- **街ごとの育成状況**（街ごとのレベルと累計学習時間の一覧）
- **通算の夜の天気アルバム**（天気ごとの夜の数。収集の進み具合は示さない）

集計の考え方は月次サマリー（4.2）に揃える。対象は**学習記録が存在する学習日のみ**とし、天気は**夜の数**で数える（1晩に複数回学習しても1回）。写真は含めない。

集計は**アプリ全体（すべての街の合計）**とする。学習記録・夜の天気は街に紐づけて保存しておらず、街ごとの累計学習時間は街の育成情報（6.1）が別に保持しているためである。ただし**街ごとの育成状況（レベル・累計学習時間）は、その育成情報から一覧として並べて表示する**。育てた街を見比べられる場所が他に無いためである。

**学習した夜の数に応じて、アルバムの表示そのものが豊かになる。** 通算では**20夜・60夜**を区切りに3段階とし、**一度到達した見え方は以後も戻さない**（通った夜は取り消されないため）。演出は街には出さない（6.1）。

段階ごとの表現は次のとおりとし、すべてコード描画で行う（素材を必要としない）。

| 段階 | 条件（通算 / 月次） | 見え方 |
|---|---|---|
| 1 | 0〜19夜 / 0〜4夜 | 飾りなし（現行のまま） |
| 2 | 20夜〜 / 5夜〜 | 星が50灯り、流れ星が1〜2つ流れる |
| 3 | 60夜〜 / 15夜〜 | 星が120に増え、夜空がほんのり明るくなる。流れ星も2〜4に増える |

星は**カレンダー画面の3つの表示すべて**（月の一覧・月次サマリー・通算のふりかえり）に灯す。基準は表示の性格に合わせ、**月の一覧と月次サマリーはその月の夜数、通算のふりかえりは通算の夜数**とする。

**星は表示領域の全面に散らし、記録の背面に敷く。** 帯のような狭い範囲に押し込めると一列に並んで見栄えが悪く、記録の前面に出すと数字やグラフが読みづらい。背面の夜空として扱い、日付やグラフはその上に置く。月の一覧では、**マスの下の余白まで含めて画面下端まで**を夜空とする（マスの高さで切ると下半分が空いて寂しく見えるため）。色は文字（白）ともグラフ（灯り色）とも変えて淡い青とし、夜空のものだと分かるようにする。**枠線は引かない**（カード自体の枠と二重になり、飾りではなく仕切りに見えるため）。**星の配置は月ごとに変える。** 同じ月を何度開いても同じ夜空になるが、月を切り替えると別の夜空になる（同じ空が並ぶと、月を移動しても景色が変わらず、月ごとの記録を見ている感覚が薄れるため）。同じ月で毎回配置が変わることはしない（表示のたびに星が飛ぶとそこへ目が行き、静かな飾りでなくなる）。通算のふりかえりは月に属さないため、配置は常に同じとする。**大きさと明るさには幅を持たせ、小さく暗い星を多く混ぜる**——粒が揃っていると模様に見え、夜空にならないためである。大きい星にのみ淡いにじみを添える。

**星はゆっくり明滅させる。** 動かすのは明るさだけで、位置も大きさも変えない。明滅の周期は星ごとにずらし、一斉に光らないようにする（揃って点滅すると信号のように見え、夜空にならない）。

**流れ星は2段階目から出す。** 空に置く数は**2段階目が1〜2、3段階目が2〜4**とし、開いたときに決める（見ている間に増減させない）。それぞれが8〜18秒に1度ほど独立して流れるため、重なることも間が空くこともある。**出る位置・流れる時間（1.2〜6秒）・流れる距離・傾きは、いずれも1回ごとに変える。** 時間と距離を別々に振ることで速さもばらつき、すっと消えるものと長く尾を引くものが混ざる。同じ場所を同じ速さで繰り返し流れると演出の反復に見え、夜空を眺めている感じが出ないためである。

**1段階目は「飾りが剥がされた状態」に見せない。** 1段階目を欠けた見た目にすると、夜が少なかった月がそのまま「サボった月」として突きつけられる。1段階目は現行のカードをそのまま完成形として扱い、2段階目以降は**続けた人へのささやかな上乗せ**として付ける。

**段階そのものは画面に表示しない**（「Lv.2」「あと3夜」等を出さない）。数値で示すと段階を上げること自体が目的になり、静かに変わるという性格が失われるためである。

ただし、**星が増えていくこと自体はカレンダーの初回説明（1.3）で一度だけ触れる。** 何も知らせないと、増えていても背景の模様として見過ごされ、続けたことへの応答になり得ないためである。この説明にも**何夜で変わるかの数値は書かない**（上記と同じ理由）。

判定に**天気の種類数（集まり具合）は用いない**。種類を条件にすると、雪や霧のように住む地域・季節によって何か月も出会わない天気があるため段階の進みが運任せになり、また上記（4.2）のとおり空欄を埋めるための天気選択を招くためである。**学習した夜の数は「その夜に学習したかどうか」の二値**であり、学習時間の長短では動かない。街のレベル（累計学習時間・6.1）とは別の軸として働き、短い夜を重ねた人にも同じように届く。

なお、**月ごとの内訳（月別の推移）はここでは扱わない**。通算は全期間をひとまとまりとして見る場所であり、月で区切って並べるのは月次サマリー（4.2）の役割だからである。

通算のふりかえりは月に依存しないため、この表示では月の切り替えを行わない。記録がまだ無い場合は、責めない静かな文言で「まだ記録がない」ことのみを示す。

## 5\. 学習セッション管理機能

### 5.1 学習時間超過時の休憩提案

その学習日の実績学習時間の合計が**最初の休憩提案の基準**に到達した時点で、休憩を提案する画面（タイマー表示上の重ね表示）を表示する。その後も学習を続けている場合、**超過60分ごと**に再表示する。

**頑張りすぎ防止設定（10.8）のON/OFFが効くのは、2回目以降の再表示のみとする。** 最初の1回＝「今回決めた分を終えた」という知らせは、設定に関わらず必ず表示する。これは長く続けすぎるのを防ぐための機能ではなく、**ユーザーが自分で決めた区切りを伝えるもの**であり、役割が異なるため。設定をOFFにすると予定学習時間が再び何の意味も持たなくなるのを避ける狙いもある。

**最初の休憩提案の基準**は、「セッション開始時点の実績合計 ＋ 今回のセッションで設定した予定学習時間」とする。すなわち**今回決めた分を終えた時点**であり、一日の学習目標時間とは切り離す。予定学習時間は黙々モード＝設定した分数、ポモドーロモード＝作業時間×繰り返し回数とし、**2つのモードで仕様を統一**する。

- 予定が目標より**長い**場合（例: 目標60分・今回90分）は90分で提案する。ユーザーが自分で決めた学習時間の途中で割り込んで急かさないため。
- 予定が目標より**短い**場合（例: 目標60分・今回30分）は30分で提案する。**「30分やる」と決めて始めた区切りを、その時点で一度知らせるため。** 目標を基準の下限にすると、目標より短く設定した予定学習時間が何にも影響しなくなり、設定した意味が失われる（ポモドーロが全ループ完了で自動終了するのに対し、黙々モードでは決めた分を終えても何も起きない、という非対称も生じる）。
- 目標に届いた時点そのものでは提案しない。目標到達は経験値を得る**肯定的な出来事**であり、休憩を促す場面ではないため（バックグラウンドでの目標到達の知らせは12章が担う）。

提案の文面は、**その夜で初めて目標に届いた瞬間のときだけ**「今夜の目標に届きました」とする。それ以外——前のセッションで既に達成している場合や、同じセッションで一度カードを出した後の再表示——は「決めた時間が終わりました」とする。達成の宣言は一晩に一度だけであり、既に達成した夜に繰り返し告げるのは事実と異なるため。

表示と同時に、休憩の時間だと気づけるよう**それとなく柔らかい効果音**（9章の「効果音」分類。急かすアラームのようには鳴らさない）を1回再生する。**鐘の音は使用しない。** 鐘は学習終了の演出（3.3）に用いる音であり、休憩提案で鳴らすと学習を継続した場合に1晩で2回鳴って意味が混ざり、鐘が「終わりの合図」として機能しなくなるため。ポモドーロのフェーズ切り替わり音（3.1）と同じ考え方に従う。

選択肢は2段階で提示する。目標に届いた瞬間に選択肢を一度に並べると、静かな体験の中で判断の負荷が高くなるため、まず大きな問いを1つ示し、続きを選んだ場合にのみ細かい選択を示す。

**1段目**

| 選択肢 | 内容 |
| :---- | :---- |
| 今夜はここまでにする | 学習を終了する。終了演出（3.3）を経て学習成果記録（3.4）へ進む。タイマー表示の終了操作と同じ動作 |
| まだ続ける | 2段目を表示する |

**2段目**

| 選択肢 | 内容 |
| :---- | :---- |
| 休憩する | タイマーを一時停止する。再開はユーザーの操作による |
| このまま続ける | 表示を閉じ計測を継続する。以後、超過60分ごとに再表示する |
| 時間を決めて続ける | 延長を宣言する（5.2） |

**「今夜はここまでにする」を用意するのは、目標に届いた瞬間は学習を終える意思が生じやすい場面であるため。** これが無いと、終了はタイマー表示の終了操作からしか行えず、提案を閉じ、タイマーを開き直す必要がある。

**続けることを選んだ場合、次に提案を表示する基準は必ず先送りする。** 「休憩する」を選んだ場合も同様に**超過60分後**を次の基準とし、再開した直後に再表示されることはない。休憩は実績学習時間に加算されないため、基準を先送りしなければ提案を閉じた瞬間に表示条件を満たしたままとなり、再び表示されてしまう。

| 選択 | 次に表示する基準 |
| :---- | :---- |
| 休憩する | 超過60分後 |
| このまま続ける | 超過60分後 |
| 時間を決めて続ける | 宣言した時間の経過後（5.2） |

**ポモドーロモード中の作業フェーズには割り込まない。** ポモドーロモードでは、休憩提案の表示は休憩フェーズまたはループ完了のタイミングで行う（休憩が組み込まれたモードであるため、作業中への割り込みは行わない）。

### 5.2 延長宣言（追加学習時間設定）

目標時間を超過してさらに学習を続けたい場合、分単位で学習の延長を宣言できる（値域: 5〜120分）。宣言した時間内は休憩提案（5.1）を表示しない。宣言時間を使い切ってなお学習を続けている場合は、再び休憩提案を表示する。

延長宣言は**休憩提案の表示制御にのみ使用し、目標達成・経験値の判定（6.2）には影響しない**。宣言した時間は当日（当学習日）のみ有効とする。

**【将来拡張】** 当初検討していた「集中モード機能（学習中の通知停止、およびアプリ利用制限機能）」は、MVPで停止できる通知が自アプリの学習開始リマインダーのみであり実質的な効果が薄いこと、アプリ利用制限にはOS側の機能との連携が必要であることから、機能ごと今回の実装対象外とする。代替として、より深い集中を求めるユーザー向けに、OSのおやすみモード・集中モードの利用を案内する文言を画面内に配置する。

## 6\. 街成長機能

### 6.1 学習時間に応じた街の成長

学習を継続することで、選択中の街が成長する。街の成長段階は**現段階（MVP）では全5段階（Lv.1〜Lv.5）とし、街ごとに個別に管理する。【将来拡張】** 将来的には10段階以上へ拡張可能な設計とする。

街の成長に伴い、建物・背景・オブジェクト・NPC・景観演出が変化する。

なお、**夜の天気アルバムに関する演出は、街には出さない**。学習した夜の数に応じて豊かになるのは**アルバムの表示そのもの**とする（4.4）。ホーム画面は「またこの世界に帰ってきたい」静けさを保つ場所であり、集めた数だけ街に物が増えていくと、その静けさが損なわれるためである。街が変化する条件は**レベル（学習時間の積み上がり）だけ**に保ち、通った夜の積み重ねにはアルバム側が応える形に役割を分ける。

街の成長状態（レベル・累計学習時間・経験値）は、**街ごとに個別管理**する。街を切り替えても各街の育成状態は保持され、再度その街を選択した際は保存済みの状態から再開する（6.4参照）。

MVPで用意する街は**2種類**とする（テーマ・デザインは素材制作時に決定する）。

各街には、任意で**サブタイトル**（上限20文字）を設定できる。サブタイトルは街名と組み合わせて「夜の街（期末テスト）」のように表示する。未入力の場合は街名のみ表示する。サブタイトルは街の育成情報に紐づく汎用項目であり、成長方式に関わらずいつでも設定・変更できる。

#### 成長処理の共通ルール

- 成長判定は、学習記録の保存（3.4）を契機に実行する。
- **累計学習時間は、選択中の成長方式に関わらず、常に選択中の街へ加算する。** 経験値は習慣型を選択中のみ付与する。
- レベルアップ判定は、条件を満たす限り繰り返し行う（一度の保存で複数レベル分の条件を満たした場合は、該当レベルまで上昇させる）。
- **街のレベルは一度上がったら下がらない**（過去に到達した最高レベルを維持する）。成長方式の切り替えや目標学習時間の変更によって判定基準が変わった場合も、このルールを適用する。
- Lv.5（街完成）到達時には、一度だけ完成演出を表示し、続けてその街の住人による完成のメッセージ（7.1 `town_completed`）を表示する。完成後も実績（累計学習時間・経験値）の加算は継続するが、レベルはLv.5で打ち止めとする。

### 6.2 街の成長方式設定

街の成長方式は、以下の2種類から選択する。成長方式は**アプリ全体で共通の設定**とし、街ごとに個別設定することはできない（成長の実績値は6.1の通り街ごとに個別管理する）。既定値は**習慣型**とする。

#### ① 習慣型 —— 毎日コツコツ続けて街を育てる

ユーザーが設定した「一日の学習目標時間」（1.2参照）を達成した学習日に、街の経験値を1獲得する。目標未達成の日は経験値を獲得しない。

- 目標達成の判定は**学習日単位の実績学習時間の合計**で行い、学習記録の保存のたびにチェックする（1日に複数セッション行った場合は合算する）。
- 経験値の付与は**1学習日につき最大1回**とする。達成した時点（達成させたセッションの保存時）に付与する。
- **一度付与した経験値は、その後同じ学習日内に目標時間が変更されても取り消さない。**

例）1日の目標時間が120分の場合: その学習日の実績合計が120分に達した時点 → 経験値+1（以降その学習日は加算なし）

経験値が一定数貯まると街のレベルが上昇する。レベルアップに必要な経験値は**一律5**とし、全ての街で共通の基準値を用いる。基準値はマスタデータとして保持し、実装後のバランス調整で変更できるようにする。

#### ② プロジェクト型 —— 目標に向かって街を完成させる

「期末テストまでに10時間」「資格試験までに30時間」のように、現実の目標に紐づいた**目標学習時間を街ごとに設定**する。学習した時間はそのまま選択中の街の累計学習時間へ加算され、目標学習時間の達成＝街の完成（Lv.5）となる。

街のレベルアップに必要な累計学習時間は、設定した目標学習時間を現在実装している5段階で均等に割った値を基準として自動計算する。

例）目標学習時間を50時間に設定した場合 Lv.1（初期状態）→ Lv.2：10時間 → Lv.3：20時間 → Lv.4：30時間 → Lv.5（街完成）：50時間

- 目標学習時間は、プロジェクト型を選択する際、および街選択画面（6.4）から設定・変更できる。
- 目標学習時間を途中で変更した場合、レベルアップ基準は再計算されるが、6.1の共通ルールによりレベルは下がらない（基準の引き下げにより新たに条件を満たしたレベルへは即時上昇する）。
- **【将来拡張】** 目標に期限（日付）を設定する機能。期限管理はユーザーを急かす方向の機能になり得るため、MVPでは合計時間の進捗のみを静かに表示する。

いずれの方式を選択した場合も、成長方式の切り替えはいつでも可能であり、切り替え前に蓄積した累計学習時間・経験値は削除せず両方とも保持し続ける。街の成長判定には、その時点で選択している成長方式の実績値のみを使用する（表示レベルは6.1のルールにより過去最高値を維持する）。

## 7\. NPC機能

### 7.1 状況に応じたNPCメッセージ表示

NPCは、学習開始・学習終了・目標達成といった基本的なタイミングで固定メッセージを表示し、ユーザーの学習を励ます。

- **住人は街に属し（`npc.town_id`）、選択中の街の住人がメッセージを出す。** 住人を他の街から連れてくることはできない——その街の景色に合った声で語られることを優先する。**1つの街に住人は複数置け、その中からユーザーが選ぶ**（当初は各街2人）。当初の配置は次の通り。**全員「責めない・急かさない・声を張らない」基調は共通で、違うのは声色のみ**（厳しい／煽るNPCは作らない）。立ち絵は将来で、当面は人物紹介文で見せる（設定10.12）。

  | 街 | 住人 |
  | :--- | :--- |
  | 夜の街 | 書店の店主（知的で静か）／夜更かし仲間（対等でくだけた） |
  | 星見の丘 | 天文台の管理人（寡黙で詩的）／焚火番の子（子どもの率直さ） |
  | 夜桜の城下町 | 茶屋の女将（温かく世話焼き）／桜守の老人（長い年月の尺度） |
  | 雪国 | ストーブ番の若者（くだけて素朴）／宿の番頭（几帳面な敬語） |

- **選択は街ごとに保持する**（`town_progress.selected_npc_id`）。街を移って戻れば、その街で選んでいた住人が迎える。未選択（NULL）のときは**その街の既定＝`id` の小さい住人**とする。**文面が未整備の住人を選んだ場合は、既定NPC（書店の店主）の候補へフォールバックする**（無言にはしない）。
- **住人の切り替えはタイマー稼働中も行える**。記録・判定に影響しない“語り”であるため制限しない（10.5の街の切り替えとは扱いが異なる）。ただし**学習セッションは開始時の住人を固定する**（`active_session.npc_id`）——その夜の終了/目標達成メッセージは開始時の住人で出し、切り替えの反映は**次のセッションから**とする。おやすみ（13章）はセッションに紐づかないため、**現在選択中の住人**で出す。
- メッセージは固定文方式とし、発生したタイミング（学習開始／学習終了／目標達成）に応じて、**選択中の住人（またはスナップショットの住人）の**候補群の中から、条件に一致するものをランダムに1件選択して表示する、単純な条件マッチ方式とする。ログイン日数・夜の種類等を組み合わせた複雑な条件判定は行わない。指定の住人に候補が無い場合のみ、既定NPCの候補へフォールバックする。
- **学習終了・目標達成のメッセージは、学習成果記録（3.4）で選択された感情に応じて出し分ける。** 感情ごとに候補群を用意し、その中からランダムに1件選択する。条件は「タイミング＋感情」の単純な一致のみとし、他の条件と組み合わせることはしない。感情が未選択の場合、および感情記録の設定（10.7）がOFFの場合は、感情を問わない候補群から選択する。
- 「目標達成」のタイミングは、学習記録の保存時に目標達成判定（6.2①）が成立した時点とする。
- **街がLv5に到達した夜は、完成専用のメッセージ（`town_completed`）を出す。** 成長方式は問わない（習慣型・プロジェクト型のどちらでも、Lv5到達は一度きりのため）。同時に成立したときの優先順位は**街の完成 ＞ 目標達成 ＞ 学習終了**とし、完成演出（6.1）を見せたあとに続けて表示する。完成のメッセージは感情で出し分けない——その夜の手応えよりも、そこまで通ったこと自体を受け止める言葉にするため。
- 用意するメッセージ量は、1体あたり感情なしの候補＋感情ごとの出し分けを加えて50種類程度（当初は各NPC52本）とする。感情ごとの候補は当初1件ずつとし、運用しながら追加できるものとする（データを追加するだけで増やせる構造とする）。街を追加するときも、その街の住人に同程度の本数を用意する。
- **文面の正は `docs/NPCセリフ集.md`** とし、そこから DB へ投入するシード（`db/seed_npc.sql`）を生成する（`npm run npc:seed`）。声色の書き分けは読み比べて推敲する作業であるため、一次資料をドキュメント側に置き、SQLは生成物とする。

例） 学習開始：「急ぐ必要はありません。夜は長いのですから。」 学習終了（感情=疲れた）：「お疲れさまでした。今夜はもう、何もしなくていい夜です。」 学習終了（感情=いつも通り）：「いつも通り。それを続けられることが、いちばん難しいのですよ。」 目標達成（感情=思うように進まなかった）：「手応えがなくとも、時間は確かに積み上がりました。届いていますよ。」

感情に応じた出し分けを行うのは、**目標に届いた夜でも手応えが無いことがあり、その食い違いを受け止める言葉こそが必要**なため。数字上の達成だけを祝う言葉は、そうした夜のユーザーを置き去りにする。

月のふりかえりメッセージ（4.2）は本NPCメッセージとは別系統（月次集計から算出する表示専用の文面でDBに保存しない）だが、**語り手は住人に揃える**。カレンダーを開いている時点で選択中の住人が振り返るものとし、月の記録は街をまたぐことがあるが、記録の集計単位は変えず、語り手だけを今の住人とする。**月次の文面を持たない住人を選んでいる場合は、同じ街の既定の住人が代わりに振り返る**（本メッセージのフォールバック先が既定NPCなのに対し、月次は街を外れた声にならないよう同じ街の中で代替する）。

**【将来拡張】** 立ち絵の追加、**1つの街の住人をさらに増やす**（構造上は人数の上限を設けていない）、固定メッセージ方式に代わるAI住人機能への拡張を予定している。NPCおよびメッセージはあらかじめ拡張しやすいデータ構造（`npc.town_id` / `npc_message.npc_id`）で管理しており、住人を足すのはマスタ行とメッセージの追加だけで済む。表示タイミングの種類も自由に追加できる。

## 8\. 深夜演出機能

時間帯に応じて空の色やエフェクトなど画面の雰囲気を変化させ、夜の街としての世界観を演出する。

背景演出に使用する「夜の天気」は、**その学習日に選択された天気**とする。選択の経路はホーム画面（2.5）・タイマー設定（3.1）・学習成果記録（3.4）の3つで、いずれの場合も選択された時点から、ホーム画面・学習中の背景演出および環境音（9章）へ即座に反映する。その学習日にまだ天気が選択されていない場合は、天気演出のないニュートラルな夜空（時刻連動の空の色のみ）を表示する。前日以前の天気は引き継がない。

天気は**学習日ごとに1つだけ保持する**（`daily_night_weather`）。**1晩＝1天気**であり、その学習日のあいだ何度でも選び直せて、**最後に選択された天気がその夜の天気として残る**。学習セッションは天気を個別に持たない（同じ夜の学習はすべて同じ天気となる）。

## 9\. BGM・効果音機能

雨音・波音・森の音・夜風・Lo-Fi BGMなど、複数の音源素材を用意し、時間帯や選択中の夜の天気（8章と同じ参照元）に応じて自動再生する。

アプリ内の音は以下の4種類に分類し、それぞれ**0〜100の音量**をユーザーが設定できる（既定値はすべて50）。

| 分類 | 内容 |
| :---- | :---- |
| BGM | Lo-Fi等の音楽。 |
| 環境音 | 雨音・波音・夜風など、時間帯・夜の天気に応じて流れる背景音。 |
| 効果音 | ボタン操作音・画面遷移音・ポモドーロのフェーズ切り替わり音などのUI音。 |
| 鐘の音 | 学習終了演出の音（3.3参照）。 |

- 音量を変更した際は、現在の音量が分かるようにプレビュー音を再生する。ただしプレビュー音を鳴らすのは**効果音・鐘の音のみ**とする。BGM・環境音は連続再生される音で、音量変更が再生中に即反映されて耳で分かるため、別途のプレビュー音は鳴らさない。
- **音量0の音は、再生処理自体を行わない**（ミュートと同義）。
- 鐘の音の再生中は、BGM・環境音の音量を一時的に下げる（ダッキング）。

#### BGMの再生とミニプレイヤー

- **BGMはホーム画面の初回表示時点では停止（デフォルト停止）とし、自動再生はしない。** 起動と同時に音が鳴るのを避け、聴くかどうかをユーザーに委ねる方針。ミニプレイヤーには最初の曲（選択中ソースの先頭）の曲名を表示しておき、ユーザーが再生ボタンを押すと**フェードインで静かに再生を開始**する（急に鳴らさない）。
- 再生する曲群は**再生ソース**で切り替える（音楽プレイリスト機能）。曲が終わると自動的に次の曲へ進む。
  - **すべて** … BGMプール（マスタデータのうちBGMに分類された音源）全曲（既定）
  - **お気に入り** … ★を付けた曲だけ
  - **マイプレイリスト** … ユーザーが追加した曲を、並び順（並び替え可）で再生。**同じ曲を複数入れられる（重複可）**
- **シャッフル**はON/OFFを切り替えられる（全ソース共通・**既定OFF**）。OFFのときは並び順どおりに再生する。ONのときは**一巡するまで同じ曲を再生しない**（並びを流し切ってから、次周で新しくシャッフルし直す）。また**シャッフルONで再生ボタンを押すとランダムな曲から始める**。
- **1曲リピート**をON/OFFできる（既定OFF）。ONのときは再生中の曲を繰り返す。
- 再生ソース・シャッフル・1曲リピートの設定は保存し、選んだソースが以後流れる。**ソースのタブを切り替えると、そのソースの先頭曲へ移る**。再生中だった場合はそのまま先頭曲を続けて鳴らし、**停止中は先頭曲に切り替えるだけで再生はしない**（再生はあくまで再生ボタンから＝デフォルト停止の方針）。
- ホーム画面下部に小型の**ミニプレイヤー**を常時表示し（タイマー計測中も表示）、以下の操作・表示を提供する。
  - 再生中の**曲名**の表示（長い曲名はスクロール表示）。アーティスト名は表示しない（見た目を簡潔に保つ）。**フリー音源のクレジット表記義務は、設定の「音楽のクレジット」（全曲＋アーティストの一覧）と、曲の「…」メニューのクレジットで満たす**
  - **再生位置の進捗バー**（曲がどれくらい進んだかを視覚的に示す）
  - **一時停止／再開**（対象はBGMのみ。環境音は天気演出の一部として流れ続ける）
  - **スキップ**（次の曲へ進む。停止中は曲を切り替えるのみで再生はしない）
  - **巻き戻し**（再生中の曲の頭に戻る。前の曲へは戻らない）
- **曲名エリアをタップするとプレイリスト画面へ遷移**し、以下を行える。
  - 再生ソースの切替・シャッフルON/OFF・再生
  - **現在再生中バー**：再生中の曲の**シークバー**（ドラッグで再生位置を移動）と経過/残り時間の表示
  - **曲をタップするとその曲を再生**する
  - 各曲の**「…」メニュー**から**お気に入りの付け外し・マイプレイリストへの追加・クレジット表示**を行う（★・追加は行に直接は置かず、メニューにまとめる）。クレジット表示は曲名とアーティスト（フリー音源の表記義務対応）を示す。**既にプレイリストにある曲を追加すると重複確認**（「この曲はすでにプレイリスト内にあります。」→「もう一度追加」/「スキップ」）を出し、「もう一度追加」で同じ曲をもう1つ入れる。マイプレイリストからの**削除（外す）は「編集」からのみ**行う
  - マイプレイリストの「編集」では**3本線ハンドルのドラッグによる並び替え**と、**複数選択＋ゴミ箱でのまとめて削除**（プレイリストから外す。曲自体・お気に入りは残る）ができる
  - **マイプレイリストの名前を編集**できる（20文字以内）。名前は上部のソースタブ（マイプレイリスト）の表示にも反映する
- **BGMの音量が0でもミニプレイヤーは表示する**（曲名タップでプレイリスト画面へ行けるようにするため）。ただし音量0では**BGMの再生処理は行わない**（音は鳴らない）ため、「音量オフ」と分かる表示を添える。
- **【将来拡張】** 複数プレイリストは行わない。

環境音は従来通り、時間帯・夜の天気に応じた自動選択・自動再生のみとし、操作UIは設けない。

### バックグラウンド再生

**BGM・環境音は、アプリを離れているあいだ（画面を消した状態を含む）も再生を続ける。** 設定でON/OFFでき（10.15参照。既定値ON）、OFFのときは従来どおりアプリを離れた時点で止まる。

学習中に画面を伏せる・他のアプリを見るといった使い方は日常的に起こり、そのたびに夜の音が途切れるのでは「その世界に留まっている」感覚が保てないため、既定でONとする。ただし連続再生は電池を使うため、戻せる設定を必ず用意する。

- **ロック画面・通知領域に再生コントロールを表示する**（曲名・アーティストと再生/停止）。Androidでは、これが無いとバックグラウンドの再生が数分で打ち切られるため必須である。
- 表示する対象は**BGMが再生中ならBGM、そうでなければ環境音**とする（OSが同時に扱える再生情報は1つのため）。環境音を表示する場合は、その夜の音であることが分かる名称（例:「雨音の夜」）とする。
- **効果音・鐘の音はバックグラウンドでは鳴らさない**（アプリが動いていないため。ポモドーロの切り替わりは通知で知らせる。12章）。
- **おやすみ（13章）で停止した音は、バックグラウンドでも鳴らさない**（おやすみは「夜を閉じる」操作であり、離れても静かなままとする）。

**実装上の制約**: 本機能は **Expo Go では動作しない**。バックグラウンド再生とロック画面の再生情報は、iOSの `UIBackgroundModes: audio`・Androidのメディア再生用の前景サービスといった**ビルド時のネイティブ設定**を必要とし、これらはExpo Goのバイナリには含まれないためである（アプリ側から `shouldPlayInBackground: true` を指定しても、背景に入った時点で再生が止まる）。動作確認には development build が必要となる。

**BGMはユーザーが曲を選べる**（お気に入り・マイプレイリスト）。曲ごとの設定は `user_sound_preference` に保持する。**環境音の個別選択は引き続き行わない【将来拡張】**。

### 10.10 アプリ内データ削除（初期化）

本機能は、アプリ内データの完全初期化機能である。実行すると、端末内に保存されている全てのユーザーデータを削除し、アプリを初回起動時と同じ状態に戻す。削除対象は以下を含む。

- ユーザー設定（ニックネーム、初期設定、各種設定）
- 学習記録・感情記録・タグ付け情報
- 街の育成状況（サブタイトルを含む）
- 夜の天気アルバム情報（学習記録から動的に生成される情報を含む）
- **その夜の写真（2.6）**。DBの記録だけでなく、**端末内に保存された画像ファイルの実体も削除する**（DBの削除だけでは実体が残るため、初期化として不完全になる）
- マイタグ（ユーザーが登録したもの）
- その他アプリ内で保存している全てのデータ

削除実行時には確認ダイアログを表示し、ユーザーが最終確認を行った場合のみ初期化を実行する。**削除されたデータは復元できない。** 初期化の完了後は、その場で初期設定画面へ遷移する。

なお、街・夜の天気・感情・NPC・NPCメッセージ・音源・成長段階の基準値などのマスタデータは、ユーザーが作成したものではないため削除対象に含まれない。

## 11\. 疑似マルチプレイ機能

ホーム画面等に、他ユーザーが同時に学習しているかのような演出として、疑似的なオンライン人数を表示する。

- **現段階（MVP）では、表示する人数はランダム生成による演出とし、実際のオンラインユーザー数は取得しない。**
- アプリ起動時に一度だけ、**3〜27人**の範囲でランダムな人数を生成し、そのアプリ起動中は同じ人数を表示し続ける。
- 人数のデータは保存しない（永続化不要な演出用データとして、アプリの動作中のみ保持する）。
- 表示文言は静かな世界観に合わせる（例:「今夜は12人が街を灯しています」）。
- **表示するのは学習を開始できる夜間帯（18:00〜翌5:00）のあいだのみ**とし、それ以外の時間帯は表示しない。昼に「今夜の学習仲間」が居るのは筋が通らず、学習を始められない時間に人数だけを見せても、置いていかれた感じを与えるだけのため。
- 配置はホーム画面右側のおやすみボタンの下とする（左上の情報の並びに混ぜず、人数だけを控えめに置く）。

**【将来拡張】** 将来的にはFirebase等のクラウドサービスを利用し、実際のオンラインユーザー数を表示する機能へ拡張する予定である。

## 12\. システム通知機能

学習開始予定時間になったら、OSのローカル通知機能を用いて通知を送信する。通知のON/OFFおよび通知時刻は設定情報として保存する（10.3参照）。

- 通知は**毎日同時刻の繰り返し**とする。通知時刻は **17:30〜翌4:30** の範囲で設定できる。この範囲は、学習タイマーを起動できる夜間帯（18:00〜翌5:00）を基準に、開始前の準備を促せるよう前側を17:30まで広げ、5:00到達で自動終了する仕様に配慮して後側を4:30までとしたものである。範囲外の時刻は設定できない（開始できない時間に開始を促す不整合を避けるため）。
- **18:00より前（17:30〜17:59）に設定された通知**は、まだ学習を開始できないため、通常の開始リマインドではなく「夜が目覚めるまであと◯分」のような、夜の開始までのカウントダウンを伝えるメッセージとする。◯分は「18:00−通知時刻」で一意に定まるため、スケジュール登録時に静的に確定できる。**18:00以降（〜翌4:30）**に設定された通知は、通常の学習開始リマインドメッセージとする。
- 通知の実現方式は、設定保存時にOSへローカル通知をスケジュール登録し、設定OFF時・時刻変更時には登録済みの通知を解除・再登録する方式とする（アプリが時刻を監視するのではなく、発火はOSが行う）。
- OSの通知許可が未取得の場合、設定をONにした時点で許可を要求する。**許可が拒否された場合は、アプリ内の通知設定をOFFに戻し、OSの設定画面から変更できる旨を表示する。**

**現段階（MVP）では、通知の送信履歴は保存しない。** 送信済みフラグや送信ログの管理は行わず、通知設定（ON/OFF・時刻）のみを保持する。**【将来拡張】** 将来的に通知の利用状況分析や送信履歴の表示機能を実装する場合は、送信履歴を保存する仕組みを別途追加する方針とする。

### 学習中のお知らせ（バックグラウンド中）

アプリがバックグラウンドにある間に起きる学習中の出来事を、OSのローカル通知で知らせる。ON/OFFは設定情報として保存する（10.13参照。既定値OFF）。3種類をまとめて1つの設定で扱う（いずれも「学習中に届く知らせ」という点で性質が同じであり、設定を分けても選び分ける基準がユーザーに無いため）。

画面を見ずに学習していると、これらの出来事に気づけない。いずれも**ユーザー自身が事前に決めた区切り**（決めた休憩・決めた学習量・夜の終わり）であり、知らせることは急かすことにはならないため、通知の対象とする。

**通知する出来事**

| 出来事 | 時刻 | 備考 |
| :---- | :---- | :---- |
| ポモドーロの切り替わり | 作業→休憩・休憩→作業の境目 | 休憩の始まりと終わりに気づけないと、休憩を挟むというモードの目的が果たせないため |
| ポモドーロの全ループ完了 | 最後の作業フェーズの終わり | **バックグラウンドでは終了演出（3.3）が走らない**ため、終わったこと自体を知らせる。終了演出・成果記録はアプリへ戻った時点で行う |
| 目標到達 | その学習日の実績合計が**一日の学習目標時間**に達した時刻 | 目標達成の判定・経験値の付与（6.2）と同じ基準。1学習日につき実質1回だけ鳴る（到達後は保存済み実績が目標を超えるため） |
| 5:00自動終了 | 学習日の終わり（3.2） | 計測中にのみ起こる。実績は5:00までで確定し、アプリへ戻った時点で終了処理へ進む |

- **目標到達の基準は「一日の学習目標時間」とし、休憩提案（5.1）の基準（`break_suggest_threshold_minutes`）は用いない。** 休憩提案の基準は割り込みの頻度を制御するための値であり、「このまま続ける」で+60分、延長宣言で別の値へと動くため、途中から目標とは呼べない数字になるためである。また同基準は「今回の予定学習時間を終えるまで割り込まない」設計のため、ポモドーロではセッション中にほぼ到達せず、通知が事実上機能しない。目標達成の判定・経験値の付与（6.2）と同じ基準に揃えることで、街が育つ節目と知らせが届く節目が一致する。
- **目標到達は、モードに関わらず到達した時刻に通知する。** アプリ内の休憩提案はポモドーロの作業フェーズ中には割り込まず次の休憩まで待つ（5.1）が、バックグラウンドの通知は画面を占有せず作業を中断させないため、待たせるより知らせる方を採る。
- 目標到達の通知は**頑張りすぎ防止（10.8）の設定に依存しない**。同設定は休憩の提案（割り込み）のON/OFFであり、目標に届いたことを知らせるかどうかとは別の話であるため。
- 実現方式は、**セッションの状態が変わった時点で、以後に訪れる出来事の時刻をすべて算出してOSへ予約する**方式とする（アプリが時刻を監視するのではなく、発火はOSが行う）。予約し直す契機は、タイマーの開始・再開・一時停止・終了とする（目標時間は計測中に変更できないため（10.2）、セッションの状態以外に予約が動く要因は無い）。
  - **一時停止中は予約を解除する**（停止中は時間が進まず、予約済みの時刻が実際とずれるため）。再開時に、その時点の残り時間で予約し直す。
  - 5:00（自動終了。3.2）より後に当たる出来事は予約しない。セッションが先に終わる場合（ポモドーロの全ループ完了より後の目標到達など）も同様とする。
- **アプリがフォアグラウンドにある間は通知を表示しない**（切り替わり音（3.1）・休憩提案（5.1）・終了演出（3.3）で既に伝えているため、通知が重なると静けさを損なう）。
- **本通知はOS標準の通知音を鳴らす**。学習開始リマインド・予定のお知らせは無音のままとする。前者は画面を見ていないユーザーに気づいてもらうことが目的であり、無音では機能しないため。後者は時刻の知らせであり、静けさを優先する。**【将来拡張】** 世界観に合う独自の通知音への差し替え（development build が必要）。
  - 5:00自動終了の通知も音を鳴らす。就寝中の可能性がある時刻だが、**この通知は計測中にしか発生せず**（学習を終えていれば鳴らない）、無音では夜が終わったことに気づけないため。
- 文面は他の通知と同様、責めない・急かさない表現とする。
- OSの通知許可が未取得の場合、設定をONにした時点で許可を要求する。許可が拒否された場合の扱いは上記と同じ（設定をOFFへ戻す）。

## 13\. おやすみ機能

一日の学習の終わりに「夜を閉じる」ための機能。ホーム画面のおやすみボタン（月アイコン等。カレンダー・設定アイコンと並べて配置）から実行する。

- ボタンを押すと、「眠りにつきますか？」等の世界観に合わせた文言で確認表示を行う。
- 確定すると、BGM・環境音をフェードアウトし、画面を暗転させる（**シンプルな暗転のみ**とし、街の灯りが消えていく差分演出は行わない）。暗転画面には、選択中の街の住人のおやすみメッセージを一言表示する（7.1）。
- 暗転中はすべての音の再生処理を停止する。ユーザーはこの状態で安心してアプリを閉じられる。
- 暗転画面をタップするとホーム画面へ復帰する。このとき**環境音はフェードインで再開する**が、**BGMは停止のままとする**（BGMはデフォルト停止であり、再生はユーザーが再生ボタンで始める。9章）。一度おやすみした後でも、いつでも戻れる。
- **タイマー稼働中（一時停止中を含む）はおやすみボタンをグレーアウト**し、タップ時に「学習中はおやすみできません。先に学習を終えてください」等の控えめなメッセージを表示する。

なお、iOSではアプリが自分自身を終了させること（プログラムによる自己終了）がAppleの審査ガイドラインで認められていないため、本機能はOSレベルのアプリ終了は行わない。「音を止め、画面を閉じ、安心してアプリを離れられる状態を作る」ことを目的とした演出機能と位置づける。本機能は演出のみであり、保存するデータを持たない。

### 主要な画面遷移

- 起動 → 初期設定（初回のみ）→ ホーム／起動 → ホーム（2回目以降）。未終了セッションがある場合は復元して終了処理へ誘導。
- ホーム → 学習開始ボタン →（夜間帯判定）→ タイマー設定モーダル → 学習タイマー表示 →（終了演出）→ 成果記録 → ホーム。
- ホーム →（18:00以降・天気未選択なら案内カード／または情報表示の天気の行）→ 今夜の天気の選択 → ホーム（背景・環境音へ即時反映。2.5）。
- 学習タイマー表示 ⇄ 休憩提案（頑張りすぎ防止ONかつ条件成立時）。
- 学習タイマー表示 →（×で折りたたみ）→ ホーム（計測継続・インジケータ表示）→（インジケータタップ）→ 学習タイマー表示。
- ホーム →（隅のアイコン）→ カレンダー／設定。設定 → 街選択／マイタグ管理。
- タイマー稼働中も各画面へ移動可能（変更制限は10章参照）。
- ホーム →（おやすみボタン）→ 確認表示 → 暗転画面 →（画面タップ）→ ホーム（13章）。タイマー稼働中はおやすみボタンを非活性とする。
- ホーム →（鑑賞モードボタン／端末を横向きにする）→ 鑑賞モード（UI非表示）→（画面タップ／縦向きに戻す）→ ホーム（2.4）。横画面は街の全景＋最小情報表示（日付・現在時刻・バッテリー残量・タイマー経過）の閲覧専用で、タップは情報表示の表示/非表示切替、タイマー操作は不可。
